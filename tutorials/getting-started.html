Getting Started

Everything from creating a config to watching the bot run your first scenario. Almost all of it works identically on Windows and Android — the toggle below switches the few parts that don't.

I'm running the game on
1

Create a config

A config holds one game's whole setup — its screens, actions, and scenarios. Click the + button next to the Loaded config dropdown at the top of the window.

  1. Type a name for the config and confirm.
  2. Type the name of the application/game it's for (free text, shown later in the Configs tab).

Game Bot Creator immediately asks how the bot should reach this game — that's Part 2, next.

2

Connect it to your game

Pick Windows (a linked desktop window) or Android (via emulator) — this can't be changed later without recapturing everything, so pick whichever matches how you actually play.

Windows

  1. Make sure the game is already open somewhere on screen.
  2. Pick it from the list of open windows, or click Later to link one afterward from the Screen Editor's Link Window… button, once the game is actually running.
For best results, run the game windowed or borderless-windowed rather than exclusive fullscreen — exclusive fullscreen can block the window from being captured at all. Use as large a window size as you comfortably can; bigger, more detailed captures hold up better if you ever move this config to a different PC/resolution.

Android

Android mode needs the free LDPlayer emulator, with your game already installed inside it:

  1. Download and install LDPlayer (a button for this is right in the dialog if it isn't found automatically).
  2. Launch LDPlayer and install your game inside it — via its own app store, or an APK.
  3. In that LDPlayer instance: Settings → Other settings → ADB debugging, set to Open local connection (one-time, per instance).
  4. Back in Game Bot Creator, click Continue — it picks up your LDPlayer install automatically.

Then:

  1. Pick which LDPlayer instance this config uses (skipped automatically if you only have one).
  2. Pick the game's package from the list of installed apps — or click Later to finish both of these afterward from the Configs tab's Link Instances… button.
3

Build your first screens

The Screen Editor tab is where you teach Game Bot Creator to recognize each distinct screen in your game, and what it can do on each one. This example builds two screens — a Home screen and one it can navigate to and back from.

Android note: every capture below pulls a screenshot from your linked LDPlayer instance instead of your physical screen — otherwise this whole part works exactly the same as Windows.

The Home screen

  1. Click + Add, name it Home.
  2. Select the screen_marker row in the table and click Recapture: drag a box around a small, unique part of this screen that's always visible (a logo or title works well), then drag a slightly larger box around where it should be searched for (or press Esc to auto-pad around it).
  3. Click Set as Home — the screen the bot treats as its home base and falls back to for recovery.

A second screen

  1. Click + Add again, give it a name (e.g. Farm).
  2. Capture its marker the same way — something only visible on this screen.
  3. Click + Add Action, choose Back, and set how the game actually leaves this screen (an image button, a fixed point, or a key press like Esc). Every screen except Home needs one.
  4. Click + Add Action again, choose Click Image, and drag a box around a button that does something here (e.g. collects a resource) — name it.

Wire the navigation

  1. Select Home in the list.
  2. Click + Add Action, choose Navigate, drag a box around whatever button on Home opens the second screen, name it, and pick that screen as the destination.

That's enough for the bot to path from Home to your second screen, act, and find its way back — automatically.

4

Build a scenario

A scenario tells the bot what to actually go do, on a repeating basis. Open the Scenario Editor tab.

  1. Click + Add — a new scenario is created and selected.
  2. Name it, and set a Cooldown seconds — how long to wait after it finishes before it can run again.
  3. Click + Add Step: set Navigate to: your second screen, and check the action you added there.

There's no Save button — every change here autosaves within about half a second. Each step's own navigation already computes the shortest path from wherever the bot currently is, so this scenario can run from anywhere reachable, not just from Home.

5

Turn it on and run it

A config only runs once it's marked Active — this keeps editing separate from running.

  1. Open the Configs tab and tick Active next to your config.
  2. If you clicked Later back in Part 2, link an LDPlayer instance now via Link Instances… on the same row — Active stays disabled until at least one is linked.
  3. Switch to the Start tab and click Start on your config's row (or Start All).

The bot detects the current screen, paths to your second screen, runs the action, comes back, and waits out the cooldown before doing it again. Watch it happen live in the Logs pane right there on the Start tab.

One at a time on Windows: only one Windows-mode config can be Active at once, since they'd fight over the same physical screen/input.
Android scales further: link a config to several LDPlayer instances and it runs identically in parallel across all of them — and more than one Android config can be Active at once, each on its own instance.

Where to go from here

  • Check (in the Add Action picker) detects an image without clicking it — useful as a prerequisite, e.g. "only run this scenario if a resource icon is full."
  • Alternates, on a flow step, watch for an unexpected popup (like an ad) mid-step and react without aborting the whole scenario.
  • Depends on, on an individual action, makes it wait for another action in the same step to have already fired first.
  • The AI tab trains an object-detection model instead of matching a fixed image — see the Training a Detection Model and Kaggle Training Setup tutorials.
  • The Jobs tab tracks every long-running background job — training runs, auto-labeling — with its own progress log.
